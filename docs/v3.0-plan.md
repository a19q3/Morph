# Morph 3.0 — Conditional Batch Settlement

## Why this is a major version

Morph 2.x could sign balances and Factory rights, but it could not leave a
bounded set of unresolved game/payment outcomes under CKB enforcement. A game
server could report results to an application, yet a unilateral close had no
native preimage/timeout path. Morph 3.0 adds a new descriptor version, Vault
lock-args version, contract, witness, package schema, and release profile. Those
are consensus and wire changes, so the correct version is 3.0.0.

## Chosen architecture

A v3 bilateral state commits one fixed 828-byte descriptor. It contains two
settlement locks, their unconditional capacities, and zero to eight sorted
conditional transfers. Every transfer binds its own ID, payer, hash algorithm,
payment hash, amount, and canonical absolute-block refund height.

The cooperative path signs the next empty v3 descriptor. Known preimages pay
the receiver and unrevealed conditions are mutually cancelled to the payer.
This needs no on-chain timeout.

The dispute path is deliberately two-stage:

1. State/Vault finalisation moves the entire CKB Vault into exactly one
   `morph-batch-lock` cell. Vault args pin the Batch Lock code hash and hash
   type, while Batch args bind channel ID, state number, and descriptor hash.
2. The Batch Cell is consumed with one fixed resolution witness. Each transfer
   either supplies the exact preimage or uses an input `since` at/after its
   absolute refund height. The transaction must create exactly one plain output
   for each participant with the script-computed capacity.

Keeping the whole Vault together avoids the occupied-capacity and fee leakage
problems of creating one cell per conditional transfer. Eight leaves bound CKB
VM work, witness size, and application retry complexity.

## Modules delivered

| Module | Morph 3.0 implementation |
| --- | --- |
| Conditional state model | `morph-core::conditional`, canonical batch IDs, SHA-256/CKB-Blake2b hashes, cooperative and force resolution |
| Channel state machine | `MorphBilateralChannelBackend` lifecycle: armed, force-closing, cooperative-settled, force-settled |
| On-chain escrow | `morph-batch-lock` plus Vault descriptor-v3 materialisation |
| Recovery package | `morph.conditional_batch_package`, CLI generation/validation fixture, exact descriptor/witness/payout checks |
| Persistence/API | Morph Hub imports only channel/funding/state-linked packages and restores them durably |
| Deployment | Eight-contract manifest; new channels pin the reviewed Batch Lock identity in Vault args v2 |
| Verification | Host invariants, parser tests, negative preimage/timeout/value tests, and CKB-VM Vault/Batch tests |

## Fixed safety invariants

- Batch IDs derive from channel ID, funding context, armed state number, and
  application-context commitment.
- Transfer IDs are strictly sorted and unique; payment hashes are unique.
- Participant settlement locks are non-zero, sorted, and distinct.
- No transfer amount is zero, and all additions are checked for overflow.
- Only exact 32-byte preimages are admitted.
- Refund heights use absolute block-number `since`; relative/timestamp/epoch
  encodings fail closed.
- Descriptor total equals Vault/Batch input capacity.
- Batch resolution creates exactly two plain participant outputs whose sum is
  the complete input value.
- Conditional batches are CKB-only in this release. Typed Vault inputs fail.

## Intentionally deferred

- conditional xUDT transfers;
- more than eight simultaneous leaves;
- routing unresolved conditions across multiple Morph channels;
- a production game-server oracle or key custody service;
- mainnet deployment and production watchtower auto-broadcast evidence.

Applications such as Counter-Strike should commit a match/session transcript
hash as `application_context_commitment`, allocate one transfer per bounded
round or payout, reveal outcome preimages after authoritative result finality,
and retain the force-resolution package with an independent watchtower. The
game server supplies facts; CKB scripts enforce only the committed financial
consequences.
