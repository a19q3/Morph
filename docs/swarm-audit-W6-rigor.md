## 1. Executive Summary

严密度评级: **devnet-research-only**.

Protocol formal-correctness has materially improved post-W5: `state_context_matches_splice_next` now binds successor `payload_commitment` to signed `new_payload_commitment` (`morph-script-common/src/lib.rs:954`), SpliceHeader is fixed at 389 bytes with both `payload_commitment` and `new_payload_commitment` fields (`morph-script-common/src/lib.rs:13,624-630`), and the `morph-sponsor-lock` first-publication bypass from W1-01 is closed at `morph-sponsor-lock/src/main.rs:117-141`. The signing domains (12 `_DOMAIN` constants in `crates/morph-core/src/hash.rs:9-17` and `contracts/morph-script-common/src/lib.rs:139-161`) are internally consistent across script-common, host-core, and tests; no orphan / collision-prone constants found in repo. State-machine coverage is complete for the bilateral profile: every (GroupInput, GroupOutput) shape in `morph-state-type/src/main.rs:56-80` maps to a transition validator; factory reduced paths enumerate all 4 reduced proof kinds in `morph-script-common/src/lib.rs:1226-2088`.

The 14 new findings below concentrate on **post-W5 rigor gaps**, not on (still-open) findings that W1-W5 already documented as open:

- **High-severity gaps cluster around host-script drift**: the host-side `SpliceTransition` struct lacks a `next_state` field (which the script-side has, and uses to bind `payload_commitment`), so `validate_splice_transition` cannot enforce the post-splice state context. This is a top rigor finding (W6-RIGOR-01).
- **`same_context_except_progress` asymmetry**: the script-side has 2 separate functions (`matches_current_state` + `state_context_matches_splice_next`) that together bind 18+ fields including the splice-time ones; the host-side single function only checks 12 fields, and the corresponding proptest only covers 12 (W6-RIGOR-04).
- **Defense-in-depth gaps** that W1 documented but were not closed in this pass: factory reduced-exit reserve conservation does not cross-check `state_root` (W6-RIGOR-03), `find_unique_state_input` iterates whole-tx (W6-RIGOR-02), `find_splice_witness_raw` has no cap (W6-RIGOR-09), `Box::leak` per-invocation (W6-RIGOR-07), `load_input(0, Source::Input)` reuse across scripts (W6-RIGOR-08).
- **Documentation-only gaps**: `validate_reduced_exit_local_evidence`'s `state_number == 0` requirement (W6-RIGOR-10), `Phase::Funding` / `Phase::Closed` are dead enum variants (W6-RIGOR-11), `WitnessEnvelope` body-length dispatch (W6-RIGOR-13).

The bilateral profile remains auditable: every paper/audit-matrix invariant has either a script-side enforcement or a host-side test (audit-matrix.md rows 1-23 all map to `invariants.rs` test names). The factory profile remains a design framework: 7 of 7 envelope kinds route correctly in `morph-factory-type/src/main.rs:128-162`, but the host-side `validate_factory_*` predicates in `crates/morph-core/src/validation.rs` do not bound `touched_participants` against `witness.participants_commitment` — they trust the script-side signature check, which is correct in principle but a rigor gap if a future deployment bypasses the script.
